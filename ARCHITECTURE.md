# Regaged Architecture

Shared systems for consistency and future game modes.

## Shared Systems

### 1. System Messages (`src/lib/systemMessageTypes.ts`, `src/components/chat/SystemMessageRenderer.tsx`)

- **Types:** DAY_CHANGE, NOMINATION, VOTE_RESULT, PLAYER_ELIMINATED, DROP_SPAWN, HEALTH_CHANGE, POV_RESULT, GAME_FINISHED
- **Renderer:** `SystemMessageRenderer` handles both structured JSON payloads and legacy body formats (`[SYSTEM:NOM_VOTES]`, `[SYSTEM:EVICT_VOTES]`, `[CASTDROP:...]`)
- **Usage:** Both Fastings (ChatPanel) and Castings (CastingChatPanel) use the shared renderer
- **New game modes:** Import `SystemMessageRenderer` and pass `body`, `createdAt`, etc. System messages are only generated by the server

### 2. Chat

- **Model:** `GameMessage` (PUBLIC channel), `GamePmMessage` (PMs)
- **API:** `POST /api/game/[id]/chat` creates messages; `/api/game/[id]/state` returns paginated messages
- **Client:** Append new messages optimistically; avoid refetching full history

### 3. Cron Tick (`src/lib/runTick.ts`, `src/app/api/cron/tick/route.ts`)

- **Internal tick:** When the Node server starts, `src/instrumentation.ts` runs `runTick()` every 60s (configurable via `TICK_INTERVAL_MS`), so games advance without an external cron.
- **HTTP endpoint:** `GET/POST /api/cron/tick` also runs the same tick (for CronPinger, external cron, or Vercel crons). Auth: `CRON_SECRET` or `x-vercel-cron: 1` or logged-in user.
- Logic: processes **active games only** (ROUND_NOMINATE, ROUND_VOTE); sequence: CASTING_BOT → FASTING → FASTING_BOT → CASTING; Casting: advance + drops + health decay; Auctions: creates/resolves from designs.

### 4. Auction House

- **Creation:** Cron creates auctions from designs when 2-day voting ends. Top-voted design per type (even with 0 votes) goes to auction
- **Bidding:** Highest bidder wins (`currentBidUserId`); bid must exceed `currentBid`
- **Duration:** 7 days per auction

### 5. Castings Mechanics

- **Day 1:** 12 hours (configurable via `CASTING_DAY_SECONDS`), inactivity deaths, no nominations
- **Day 2+:** Calculate scores → nominate 3 lowest → voting → 1 eliminated
- **Drops:** Apple/Key/Poison; spawned by cron; claim via `SystemMessageRenderer` in chat

## Adding a New Game Mode

1. Add `GameType` in Prisma schema
2. Create `gameEngineX.ts`, `advanceX.ts`, `votesX.ts`, `nomsX.ts` (reuse patterns from fasting/casting)
3. Extend cron tick to process the new type (filter by `gameType`)
4. Use `SystemMessageRenderer` for system messages
5. Add enrollment page and game UI (reuse RightRail, chat components)
